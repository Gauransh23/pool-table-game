# Implementation quality contract

For changes to physics, geometry, aim/power/spin, presentation/audio, recovery or export performance, read [QUALITY_TARGETS](docs/quality-roadmap/QUALITY_TARGETS.md) first, then the relevant generated target branch and [TEST_PROTOCOLS](docs/quality-roadmap/TEST_PROTOCOLS.md).

Choose requirement IDs for each bounded checkpoint and report actual evidence against them. Existing regression totals establish only their documented coverage. Preserve target thresholds and failed fixtures; revise targets through a recorded evidence-backed contract change. Keep the active gameplay engine and its acceptance tests aligned.

Use [TASK](docs/quality-roadmap/TASK.md) for workflow state and [NEXT_CHECKPOINT](docs/quality-roadmap/NEXT_CHECKPOINT.md) for the next numerical action. The experimental impact stepper remains outside gameplay until its promotion gates pass.
