# Computational pool simulator and validation source map

Research checked: 2026-11-04. Scope: original computational billiards methods, first-party simulator code and documentation, and public measurements or datasets that could ground later physics validation. This is a source map and coverage audit; it makes no implementation proposal.

## Short read

The best computational references serve different evidence roles. Leckie and Greenspan's event-based PoolFiz work is the foundational algorithm source: it computes motion and event times analytically under its chosen motion/collision model. That is algorithmic precision, not proof that its coefficients or collision laws match a particular table. Pooltool is the strongest inspectable research implementation located: its current repository has event-based evolution, selectable collision resolvers, examples, and numerical/regression tests; one test reproduces published Mathavan ball-ball results. Its JOSS paper describes the package, not an end-to-end real-table error benchmark. For actual calibration evidence, use the original high-speed experiments and treat the 2026 CUE work as an active-calibration lead whose real-table results remain a demonstration rather than a reported quantitative benchmark.

The project already tests several analytic invariants well. The missing layer is measured, held-out trajectories from a named table and shot condition, especially where spin, simultaneous contacts, cushions, and pockets interact. The detailed local coverage inventory is in [Physics validation](../../PHYSICS_VALIDATION.md); the native test names and assertions are in [physics_core_tests.cpp](../../native/tests/physics_core_tests.cpp).

## Evidence boundary

Keep these claims separate when the sources are used later:

1. **Analytic consistency:** a state transition or collision matches an equation under named assumptions (for example, elastic/frictionless equal-mass collision, rolling resistance, or a root-derived event time).
2. **Numerical reliability:** the solver selects the right real event root, preserves ordering, and remains stable for near-grazing, near-simultaneous, and extreme-scale cases.
3. **Empirical realism:** predicted time histories, event times, paths, exit velocities/spins, pocket outcomes, and settled positions agree with measurements from specified equipment, with uncertainty and held-out cases.

Event-based simulation mainly strengthens (1) and can help with (2); it does not establish (3) without measured comparison. A large deterministic regression suite can therefore pass while the default cloth, collision, rail, or pocket coefficients remain poorly calibrated for the target table.

## Scenario coverage absent or still thin in this project

The local validation report already identifies convergence, real-rail calibration, cluster cases, pocket jaws/shelf, break sweeps, long-run stress, and Native/GDScript parity as gaps. Comparing its current listed analytic tests with the sources above leaves these particularly valuable *scenario families* unrepresented or not yet backed by measurements:

- **Measured free motion:** several launch speeds and top/bottom/sidespin states, tracked through slide-to-roll/overspin, side-spin decay, and stopping distance on a named pool table. This would distinguish parameter fitting from the current analytic friction checks.
- **Measured collision matrix:** cuts across impact speed and incoming spin, including stun, rolling, draw, and sidespin, with both balls' post-impact speed and direction and their post-slide outcomes. The 2014 Mathavan cases are useful seeds, but are too small to stand in for this matrix.
- **Rail response matrix:** normal/tangential speed, incidence angle, topspin/backspin/sidespin, rail segment/jaw, and rebound speed/direction, using the tested range of a named measured model/table. Existing symmetry/energy references do not cover real rebound response.
- **Pocket boundary cases:** slow/fast and shallow/steep approaches; jaw-first versus facing/shelf contact; hanging ball, rattle, fall, and near-miss distinctions. Geometric mouth dimensions alone are not outcome calibration.
- **Coupled and repeated contacts:** simultaneous or near-simultaneous clusters, moving-ball impacts, rail-ball-pocket sequences, airborne landing followed by collision, and multi-rail breaks. Keep timestep/convergence or event-order stability separate from measured realism.
- **End-to-end held-out shots:** capture initial conditions and video/tracking reference for ordinary shots, banks, safeties, and breaks on the same table; compare event sequence and final state as well as per-ball trajectories. Existing match-video datasets can add variety, but the laboratory sources offer more precise physical observables.

These are coverage labels for future evaluation, not implementation instructions. Current project evidence and already-listed gaps remain summarized in [PHYSICS_VALIDATION.md](../../PHYSICS_VALIDATION.md).
