# Engineering decisions

Last updated: 2026-10-27

## Engine: Godot 4.7.2 stable Standard

**Alternatives considered:** Godot 4.8 beta; a custom native renderer and simulation;
and a native app per platform. The official release archive lists 4.7.2 as stable and
4.8 as beta. Godot matches the brief's cross-platform default and keeps one
presentation stack for the four requested targets. The Standard build avoids the
.NET runtime and extra managed deployment surface.

**Revisit when:** a representative build or benchmark exposes a material platform,
physics, performance, or maintenance limitation.

## Simulation: GDScript runtime, standalone C++ experiment

The GDScript core remains the playable reference. Its latest four-second 16-ball
break took 288.4–291.6 ms (median 289.9 ms) in Godot's headless editor/debug build on
this M4 host. A separate C++17 core with double-precision state and no Godot types now
builds through the system C++ compiler. It uses 1/480-second ticks, adaptive
substeps, time-of-impact normals and timestamps for ball and cushion contacts, and a
standalone event stream. Its seven-run optimized 16-ball benchmark took 3.76–6.19 ms
(median 4.25 ms). This is about 68× faster on these measured paths, but the builds
and outputs are not yet parity-verified, and the C++ core is not integrated into the
game.

The 1,601-point analytic cut sweep is smooth to floating-point precision at
0.0001-radian increments. The native solver still advances a full substep before
resolving overlaps and applies position correction; it is not yet a full event-driven
or continuous collision solver. Next compare its state and event output against the
GDScript reference, then test a GDExtension bridge and measure both the wrapper and
the game runtime. Keep AI search behind those gates.

## Rules: event-driven profile, separate from simulation

The first rules profile follows core WPA 8-ball called-shot behavior, including the
temporary cleared-group claim for an open-table 8-ball shot, and returns turn, foul,
break-choice, and rack-outcome data. It consumes shot events; it never changes ball
trajectories. The rules module is isolated and tested, and integration with a real
collision/pocket event stream is a separate step.

## Time stepping: 480 Hz baseline plus adaptive collision substeps

The step is a starting experiment, not a claim of physical accuracy. Adaptive
substeps use maximum ball travel to reduce missed contacts. Keep render timing
separate. Convergence results and large break batches must set final parameters.

## Pocket entry: open cushion segments, jaws, exit regions, and gravity drop

An ordinary pocket is not a large circular trigger. The current table defines six
mouth openings, jaw segments, and separate corner/side capture regions. Once a ball
passes the mouth, it enters a falling state and disappears only below the table. A
future full pocket model must add measured jaw profiles, shelf length, and return
geometry.

## Visual identity: Long Rail

Use deep green cloth, smoked walnut, warm metal, soft room lighting, and restrained
cream UI. Balls and table geometry remain the visual focus. All current materials and
meshes are generated by project code; no competitor art or audio is used.

## Mac preview checkpoint — 2026-10-28

Owner steering prioritizes visual fidelity and implemented physical feel over feature
breadth for the first installable draft. Ship a practice preview for feedback on
force, friction, collisions, aiming, and rendering. Full match UI/AI remain behind
physics and presentation quality. The preview keeps the GDScript runtime with
TOI-informed ball normals; native integration remains separate engineering work.
